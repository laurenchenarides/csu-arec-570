APIs deliver secondary data

The organization responsible for the source determines

  • What is measured
  • Which people, places, or activities are covered
  • When observations are collected and released
  • How uncertainty, missing values, and revisions are recorded

An application programming interface provides a documented way for R to request selected records from that source

Lecture 5.1 introduced primary and secondary data. An API is one way to receive secondary data collected and maintained by another organization.

What happens when R calls an API

R function→request→data service→response→R object \text{R function} \longrightarrow \text{request} \longrightarrow \text{data service} \longrightarrow \text{response} \longrightarrow \text{R object}

  • Endpoint is the web address for a data service
  • Parameters specify the place, time, variables, and other selections
  • Response is the information returned by the service
  • R package translates the response into a familiar object

Many services transmit a structured text format called JSON. The packages in today’s examples read that format and return a data frame, map, or raster

A retrieval workflow

  1. Read the source documentation
  2. Define the place, time period, variables, and unit of observation
  3. Run a small request
  4. Inspect column names, values, units, and missingness
  5. Save the returned file or object
  6. Record the request and retrieval date
  7. Expand the request after the checks are complete

A small request might cover one county, one station, or one month. This keeps errors visible and makes it easier to learn the returned structure.

Example 1: land use

Question

Which crop and land-cover classes does the Cropland Data Layer assign in Larimer County in 2024?

Source

USDA NASS Cropland Data Layer through the CropScape service

Observation

Each raster cell has a modeled crop or land-cover class for a particular year

CropScape documentation | CropScapeR documentation

Request a Cropland Data Layer map

library(CropScapeR)

larimer_cdl <- GetCDLData(
  aoi = "08069",
  year = 2024,
  type = "f",
  save_path = "data/raw/cdl_larimer_2024.tif"
)

raster::plot(larimer_cdl)

08069 is the five-digit Census code for Larimer County

The saved GeoTIFF contains a grid of land-cover codes and the information needed to locate those cells on a map

Use the land-use data

  • Map crop locations
  • Calculate acreage by crop class
  • Compare annual crop patterns
  • Define land-use exposure near water infrastructure or development

Try it: summarize land-cover records

Change selected, then run the cell. The classroom extract has the same class-and-acreage structure used in a CDL summary

Assess the land-use data

  • Crop-class definitions for each year
  • Classification accuracy for the study region and crop
  • Pixel resolution and coordinate system
  • Treatment of double cropping and small fields
  • Consistency of the study boundary across years

The CDL records modeled land-cover classes. Parcel ownership, zoning, and management practices require additional sources

Example 2: water

Question

What was the daily flow of the Cache la Poudre River during the 2024 growing season?

Source

USGS Water Data API

Observation

Each row reports a daily statistic for one parameter at one monitoring location

USGS monitoring location 06752260 | dataRetrieval tutorial

Request daily streamflow

library(dataRetrieval)

poudre_flow <- read_waterdata_daily(
  monitoring_location_id = "USGS-06752260",
  parameter_code = "00060",
  time = c("2024-04-01", "2024-09-30")
)

names(poudre_flow)
head(poudre_flow)

00060 is the USGS parameter code for discharge

The returned columns include date, value, unit, approval status, qualifiers, station geometry, and a time-series identifier

Try it: define a low-flow threshold

Change threshold, then run the cell. The compact series represents the date and value columns returned by the water request

Assess the streamflow series

  • Confirm the monitoring location and parameter
  • Read the unit attached to each series
  • Examine provisional and approved status
  • Identify missing dates and changes in the operating record
  • Learn whether reservoirs, diversions, or return flows affect the gauge
  • Define the geographic relationship between the gauge and the study area

The gauge measures conditions at one point on a river network. A study of irrigation access may also require diversion service areas, water rights, or delivery records

Use the read_waterdata functions for the modern USGS Water Data APIs. USGS plans to decommission the services used by readNWIS functions in 2027.

Example 3: weather

Question

What temperature and precipitation conditions occurred near Fort Collins during the 2024 growing season?

Source

NASA Prediction Of Worldwide Energy Resources or POWER

Observation

Each row reports modeled weather conditions for a grid cell and day

NASA POWER documentation | nasapower documentation

Request daily weather

library(nasapower)

fort_collins_weather <- get_power(
  community = "AG",
  lonlat = c(-105.08, 40.58),
  pars = c("T2M_MAX", "T2M_MIN", "PRECTOTCORR"),
  temporal_api = "daily",
  dates = c("2024-04-01", "2024-09-30")
)

head(fort_collins_weather)

AG selects parameters prepared for agricultural applications

The three requested measures are maximum temperature, minimum temperature, and precipitation

Use the weather data

  • Count high-temperature days
  • Calculate growing degree days
  • Sum growing-season precipitation
  • Construct weather exposures for farms, counties, or markets

Try it: define weather exposures

Change heat_threshold, then run the cell. The extract contains daily maximum temperature and precipitation

Assess the weather data

  • Grid-cell resolution
  • Coordinates assigned to each study unit
  • Parameter definition and unit
  • Time standard and daily aggregation
  • Version and revision status

POWER provides grid-cell estimates. Conditions at fields within the same cell can vary

Example 4: Census ACS

Question

How does median household income vary across census tracts in Larimer County?

Source

American Community Survey five-year estimates

Observation

Each row reports an estimate and margin of error for one variable and geographic area

Census API guidance | tidycensus documentation

Store the Census API key

Request a free key from the Census API key page

Open the user-level environment file from R

install.packages("usethis")
usethis::edit_r_environ()

Add one line to that file and restart R

CENSUS_API_KEY=replace_with_your_key

The environment file stays on your computer. Shared scripts read the key with Sys.getenv("CENSUS_API_KEY")

Request tract estimates and geometry

library(tidycensus)

larimer_income <- get_acs(
  geography = "tract",
  variables = c(median_income = "B19013_001"),
  state = "CO",
  county = "Larimer",
  year = 2024,
  survey = "acs5",
  geometry = TRUE,
  key = Sys.getenv("CENSUS_API_KEY")
)

head(larimer_income)

The result contains a geographic identifier, name, estimate, margin of error, and tract geometry

Map the ACS estimates

library(ggplot2)

ggplot(larimer_income) +
  geom_sf(aes(fill = estimate), color = NA) +
  labs(
    fill = "Median income",
    title = "Median household income by census tract"
  )

The default margin of error describes a 90 percent confidence interval

estimate±margin of error \text{estimate} \pm \text{margin of error}

Try it: use the ACS margin of error

Change relative_moe_limit, then run the cell. The classroom extract contains one estimate and margin of error for each tract

Assess the ACS estimates

  • Treat the five-year estimate as a pooled period ending in the named year
  • Retain the margin of error
  • Identify estimates with large uncertainty
  • Use geographic identifiers as character values
  • Record the tract boundary vintage
  • Adjust monetary values when comparing periods

ACS data can describe the population and socioeconomic setting for a land or water study. Exposure measures and program participation may come from separate sources

The unit changes across sources

Source Unit returned by the request Time Geography
Cropland Data Layer Raster cell Annual Grid
USGS Water Data Gauge and day Daily Monitoring point
NASA POWER Grid cell and day Daily Weather grid
Census ACS Estimate and area Five-year period Census tract

A combined dataset requires a written rule for assigning pixels, gauges, weather cells, and census areas to the study units

Combining the downloads

For every join record

  • Identifier used by each source
  • Geographic crosswalk or spatial rule
  • Time aggregation rule
  • Number of observations before and after the join
  • Unmatched locations and periods
  • Treatment of revised, suppressed, and missing values

The combined analytic sample includes the observations that satisfy all source coverage and matching rules

Connect this point to Lecture 5.1. Adding a secondary source can change the analytic sample because locations or years with complete matches may differ from the intended study population.

The reading: allocating the collection budget

Dominitz and Manski ask how to allocate a fixed budget across collection processes that differ in cost and information (Dominitz and Manski 2017)

API access reduces the time required to retrieve additional observations

Research time is also required to

  • Verify definitions and units
  • Examine coverage, missing values, flags, and uncertainty
  • Select spatial and temporal aggregation rules
  • Validate joins across sources
  • Archive metadata and retrieval records

Question: How should a researcher allocate one additional week across these tasks?

Select the access method

Project need Useful access method
A defined subset repeated across places or periods API request
Most records in a fixed release Bulk download
A few values needed once Web table or manual download
Repeated data cleaning and analysis Scripted retrieval with archived raw files

Choose the method after reviewing the source documentation update schedule and request limits

Summary

APIs provide scripted access to secondary data

R packages translate requests and responses into familiar R objects

Source documentation defines the population, measures, timing, geography, and uncertainty

Small requests make the returned structure easier to inspect

Retrieval records support reproducibility

Data joins help define the final analytic sample
